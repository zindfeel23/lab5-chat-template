# Файлы и интерфейсы

Правила команд — в [README](README.md). Здесь описаны имена функций и данные, с которыми работают решение, тесты и автопроверка. Используйте обычные функции, словари и списки.

## Состояние игры

`world.json` содержит исходные данные. Фикстура `state` читает их заново для каждого теста.

```python
state = {
    "players": {
        "lina": {
            "nick": "Lina",
            "guild": "dawn",
            "role": "master",
            "messages": [],
        },
    },
    "guilds": {
        "dawn": {"members": ["lina"]},
    },
}
```

Ключ игрока — его идентификатор. Сервер передаёт его в параметре `sender`. В аргументах команды стоят **ники**, а не идентификаторы. В `members` хранятся идентификаторы игроков. Порядок участников не важен.

У игрока без гильдии поля `guild` и `role` равны `None`. В `messages` хранятся словари вида `{"sender": "lina", "text": "привет"}` в порядке доставки. Входное состояние согласовано с правилами README; отправитель существует. Тесты могут создавать другие согласованные состояния, менять роли и ники.

Функции меняют переданное состояние. При отказе оно остаётся прежним. Добавлять журнал внутрь `state` не надо: он передаётся отдельно.

## Парсер

```python
from chat_parser import ParseError, parse_command

name, args = parse_command('/w "Sir Lancelot" привет')
# name == "w"
# args == ("Sir Lancelot", "привет")
```

`parse_command(raw)` возвращает пару: строковое имя команды без начального слэша и кортеж строковых аргументов. Для `/guild` в имя входит следующий токен: например, `guild kick`. Парсер разбирает и неизвестные имена: наличие обработчика проверяет диспетчер.

Двойные кавычки объединяют слова в один аргумент. Внутри такого аргумента `\"` означает кавычку, а `\\` — обратный слэш. Одинарная кавычка остаётся обычным символом. Пустая строка, отсутствие начального слэша или незакрытая двойная кавычка в аргументе вызывают `ParseError`.

У `/w` после получателя ровно один пробельный символ отделяет текст. Всё после него сохраняется буквально, включая остальные пробелы и незакрытые кавычки:

```python
parse_command('/w Ada   привет " /guild disband')
# ('w', ('Ada', '  привет " /guild disband'))
```

Если после получателя нет разделителя, парсер возвращает только получателя: аргумента `text` не хватает. Если разделитель есть, текст может быть пустым. Количество аргументов проверяет `bind`, а не парсер. Не меняйте `chat_parser.py` и не разбирайте текст повторно в обработчике.

## Функции в solution.py

```python
requires_role(min_role)
audit(function)
whisper(state, sender, target, text)
kick(state, sender, target)
disband(state, sender)
build_registry()
dispatch(state, sender, raw, *, registry, log)
```

Сохраните эти имена и параметры. Первые параметры можно передавать и позиционно, и по имени; `registry` и `log` у диспетчера — только по имени. Вспомогательные функции добавляйте по необходимости.

`build_registry()` возвращает новый словарь с ключами `w`, `guild kick`, `guild disband`. Значения — обработчики: `whisper`, `kick`, `disband`, причём два последних уже защищены `requires_role`. Где применять декораторы — при объявлении функций или сборке реестра — решаете вы.

Диспетчер вызывает обработчик так: `handler(state, sender, *args)`. Именно этот вызов нужно проверить через `inspect.signature(handler).bind(...)`. Новая команда получает свои параметры после `state` и `sender`; для её добавления достаточно новой записи в реестре.

`requires_role(min_role)` принимает `member`, `officer` или `master`. Оборачиваемая функция имеет параметры `state` и `sender`. `audit` работает с функцией, имеющей параметры диспетчера: `state`, `sender`, `raw`, `registry`, `log`. Дополнительные аргументы обёртки передают дальше без изменений. Для отдельного опыта с порядком декораторов используйте этот же интерфейс.

Рабочий `dispatch` уже обёрнут в `audit`: при вызове `impl.dispatch(...)` запись появляется автоматически. Повторно оборачивать его в тестах не нужно. Обработчики не ведут журнал сами.

## Результат и журнал

Успех: `{"status": "ok", "reason": None}`. Отказ: `{"status": "denied", "reason": код}`. Обёртки возвращают тот же словарь, который вернула вызванная функция, включая дополнительные поля, если они есть.

| Код отказа | Причина |
|---|---|
| `parse_error` | Парсер выбросил `ParseError` |
| `unknown_command` | Имени нет в реестре |
| `bad_arguments` | `bind` не смог связать аргументы с параметрами |
| `player_not_found` | Игрока с указанным ником нет |
| `forbidden` | Не выполнено условие о правах, гильдии или допустимой цели |

Порядок проверок: разбор строки, поиск команды, связывание аргументов, проверка минимальной роли, проверки обработчика. В обработчике сначала найдите игрока по нику, затем проверьте ограничения на цель. Проверять минимальную роль перед поиском получателя у `/w` не нужно.

Журнал — переданный список. Каждая запись имеет все пять полей:

```python
{
    "sender": "lina",
    "raw": '/w "Sir Lancelot" привет',
    "status": "ok",          # либо "denied", либо "error"
    "reason": None,          # код причины только при отказе
    "error": None,           # имя типа исключения только при ошибке
}
```

Неожиданное исключение не превращается в результат-отказ: в журнале появляются `status="error"` и, например, `error="TypeError"`, а то же исключение выходит наружу. Откат после неожиданной ошибки обработчика в этой лабе не требуется. Вызовы выполняются последовательно, без потоков и вложенных вызовов диспетчера.

## Запуск

Используйте Python 3.14.

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m pytest -q
python -m pytest -q --impl valera
```

В Windows окружение активируется командой `.venv\Scripts\activate`.

Фикстура `impl` возвращает модуль `solution` или модуль из `--impl`. Фикстуры `state` и `log` выдают новое игровое состояние и пустой журнал для каждого теста. Например, вызов диспетчера в тесте выглядит так:

```python
registry = impl.build_registry()
result = impl.dispatch(
    state, "lina", '/w "Sir Lancelot" привет',
    registry=registry, log=log,
)
```

В начальном шаблоне функции решения выбрасывают `NotImplementedError`, а тестов ещё нет. Их пишете вы. Меняйте `solution.py` и `test_solution.py`; остальные файлы автопроверка берёт из исходного шаблона.
